# Tournament Simulator

## Goal

Build a transparent FIFA World Cup 2026 simulator that shows each team's probability of reaching every stage.

## Runtime Model

Public simulations are generated by Cloud Run Jobs and stored in Cloud Firestore.

On-demand simulations run through protected Cloud Run server routes or queued Cloud Run Jobs. Custom runs must be authenticated and stored for reuse.

Simulation runs must store:

- `modelVersion`
- `assumptions`
- `inputHash`
- `runCount`
- `generatedAt`
- `expiresAt`
- `visibility`
- requester ID for private runs

## MVP Model

Use an Elo-informed independent Poisson model.

Why this is the correct MVP choice:

- Easier to explain to users.
- Strong enough for a first public simulator.
- Fast enough for repeated Monte Carlo runs.
- Can later be replaced with Dixon-Coles, bivariate Poisson, or ensemble models.

## World Cup 2026 Format

The simulator must support:

- 48 teams
- 12 groups of four
- Top two from each group advance
- Eight best third-placed teams advance
- Round of 32
- Round of 16
- Quarter-finals
- Semi-finals
- Third-place match
- Final

## Match Probability Model

The future implementation should model each match with:

- Team strength.
- Attack adjustment.
- Defense adjustment.
- Host or venue adjustment where supported.
- Independent Poisson goal expectations.
- Score matrix.
- Home win, draw, and away win probabilities.

MVP model assumptions must be documented and stored with each simulation run.

## Simulation Modes

| Mode | Purpose | Runs | Cache policy |
|---|---|---:|---|
| Public tournament probabilities | Main public simulator and team pages | 100,000 | Cache aggressively |
| On-demand user run | Custom assumptions from current state | 10,000 immediate | Store for 24h |
| Admin offline analysis | Calibration and model comparison | 500,000+ | Not user-facing |

## Firestore Storage

Store simulation metadata and compact result read models at:

```text
simulationRuns/{simulationId}
```

Public run documents must be readable by everyone. Private/custom runs must be readable only by the requester.

## Job Triggers

Public simulations should run:

- Nightly before and during the tournament.
- After major provider data updates.
- After confirmed bracket/qualification updates.
- After material team metric changes.

On-demand simulations should:

- Require authentication.
- Enforce run-count limits.
- Reuse existing results when `modelVersion` and `inputHash` match.

## Acceptance Tests

- Match probabilities sum to approximately 1.
- Group ranking handles points, goal difference, goals scored, and required tiebreaker placeholders.
- Best third-placed team ranking returns eight teams.
- Knockout advancement never returns a draw.
- Same input hash and model version can reuse cached output.
- Public probabilities have stage probabilities in valid ranges.
- Firestore simulation run document stores model version, assumptions, input hash, run count, and generated timestamp.
